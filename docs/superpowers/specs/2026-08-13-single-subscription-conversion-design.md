# Единая подписка и конвертация — дизайн

## Цель

Сделать single-режим Лазейка ВПН единым для всех способов получения и изменения подписки: trial, оплата через провайдера, баланс, подарок, админская выдача и автопродление. В single-режиме у клиента одна активная подписка, один `remnawaveUuid` и одна ссылка; условия меняются на существующем ключе.

## Главный инвариант совместимости

Текущие рабочие подписки пользователей сохраняются. Миграция и новая логика не перевыпускают, не заменяют и не пересоздают существующий канонический `remnawaveUuid`/`shortUuid`. Пользователям не требуется менять ссылку или переустанавливать VPN.

- Покупка, trial, конвертация, подарок, продление, админская выдача и автопродление никогда не вращают ссылку.
- Ссылка меняется только после явного ручного подтверждения пользователем в «Мои ключи».
- Для клиента с одной подпиской миграция не выполняет удаленных вызовов и не меняет запись.
- Для `vssarovv` сохраняется активный используемый ключ, удаляется только точно идентифицированная старая подписка.
- Для `sallyqx` сохраняется подписка «Стандарт», удаляется только подписка с точным названием тарифа «Обычный ВПН».
- Если владелец, тариф, активный ключ или удаляемая запись определены неоднозначно, миграция останавливается до любых изменений.

## Режимы подписок

Существующая настройка `multiSubscriptionsEnabled` остается обратимым переключателем.

- `false` — целевой режим по умолчанию: одна активная собственная подписка на клиента независимо от категории.
- `true` — прежняя возможность нескольких подписок сохраняется для будущего возврата функционала.
- Жесткий owner-only уникальный индекс в БД не добавляется: он сделал бы возврат multi-режима миграцией схемы.
- В single-режиме сервер сериализует операции по клиенту блокировкой строки/транзакцией и всегда выбирает каноническую запись с `subscriptionIndex=0`.
- Резерв, купленный для подарка, не считается активной подпиской покупателя. При получении подарка он обновляет канонический ключ получателя либо становится его первым ключом.

## Канонический серверный путь

Один сервис выполняет preview и применение изменения подписки. Его вызывают:

- `activateTariffByPaymentId` и все payment webhook;
- оплата балансом;
- legacy и настраиваемые trial;
- активация подарка себе или получателем;
- ручная конвертация в кабинете;
- админская выдача, продление и конвертация;
- автопродление.

В single-режиме сервис:

1. Блокирует операции конкретного клиента.
2. Повторно читает каноническую подписку и актуальные условия Remnawave.
3. Рассчитывает итог без изменения состояния.
4. При существующем ключе делает PATCH того же Remnawave user и обновляет ту же `Subscription`.
5. Создает новый Remnawave user только если у клиента никогда не было канонического ключа.
6. Синхронизирует legacy-поля `Client` для совместимости.
7. Записывает payment/subscription metadata и audit event идемпотентно.

Сбой Remnawave не приводит к созданию запасного UUID. Локальная запись помечается существующим механизмом `syncStatus/syncError` для безопасного повтора или reconciliation.

## Trial-бонус первой покупки

При первой оплаченной подписке начисляется:

`оплаченные дни + минимальная durationDays среди активных trial`.

Бонус доступен только если до операции одновременно верно следующее:

- клиент никогда не активировал trial (`trialUsed`/`ClientTrialUsage` не показывают использование);
- у клиента не было подписки;
- нет более ранней успешно активированной платной покупки;
- существует хотя бы один активный trial.

Если активных trial нет, бонус равен нулю. Если trial уже активен, отдельный минимальный бонус не начисляется: существующий ключ обновляется, а оставшийся срок trial переносится один раз по правилу trial-конвертации. Повторная оплата или бывший подписчик бонус не получают.

## Конвертация

Единицей сравнения служит фактическая цена за день с учетом выбранной price option и оплаченных дополнительных устройств.

- Тот же тариф: обычное продление, срок переносится без комиссии.
- Другой тариф с более высокой ценой за день: `raw = стоимость остатка / новая цена за день`. Переход разрешен, только если `raw >= 1`; результат `ceil(raw)`.
- Другой тариф с более низкой ценой за день: `floor(стоимость остатка * 0.95 / новая цена за день)` — комиссия сервиса 5% и округление вниз.
- Другой тариф с равной ценой за день: перенос целых дней без комиссии, округление вниз.
- Истекший остаток дает ноль дней.
- Активный trial переносит оставшиеся дни один к одному; дополнительный trial-бонус не начисляется.

Ручная конвертация применяет только сконвертированный остаток. После перехода вверх UI сразу предлагает купить еще месяц. При покупке другого тарифа сконвертированные дни добавляются сверху к купленному периоду.

Preview и применение используют одну чистую функцию расчета. Quote содержит subscription id, версию исходных условий, исходный expiry и рассчитанные дни. Перед применением сервер повторно проверяет quote; изменившийся источник не конвертируется по устаревшим данным и требует нового preview.

## Ручная замена ссылки

В «Мои ключи» доступна отдельная операция reissue канонической подписки.

- До запроса требуется явное подтверждение предупреждения, что старая ссылка и установленные по ней конфигурации перестанут работать.
- UI рекомендует выполнять операцию через обычный сайт, а не mini-app: после остановки VPN Telegram может быть недоступен.
- Лимит хранится в БД: одна успешная замена раз в 6 часов на аккаунт.
- Дополнительно применяется короткий IP burst-limit, проверка владельца, защита от параллельных запросов и audit log.
- Неудачный вызов Remnawave не расходует шестичасовой лимит.
- После revoke backend заново получает пользователя, валидирует URL строго для `https://sub.lazeika.xyz/<slug>`, сохраняет новый `remnawaveShortUuid` и время успешной ротации, затем возвращает ссылку.
- Никакой другой серверный поток reissue не вызывает.

## Кабинет и бот

В кабинете появляется действие «Конвертация» для единственной активной подписки. Оно показывает текущий и целевой тариф, остаток, направление перехода, комиссию, округление и итоговые дни до подтверждения.

При выборе оплаты другого тарифа тот же preview показывает дни, добавляемые конвертацией сверх покупки. После перехода вверх показывается действие «Оплатить еще месяц».

Бот использует те же API и расчеты. Для reissue он показывает предупреждение и рекомендацию открыть обычный сайт; серверные проверки одинаковы для сайта и mini-app.

## Админская панель

Админская выдача, продление и смена тарифа используют канонический серверный сервис. Перед применением администратор видит тот же conversion preview. Админка не рассчитывает дни самостоятельно и не создает дополнительный Remnawave user в single-режиме.

## Миграция данных

Миграция выполняется отдельным идемпотентным CLI со стадиями `dry-run` и `apply` и журналом восстановления.

Dry-run для каждого клиента фиксирует ID записей, тарифы, `subscriptionIndex`, Remnawave UUID/short UUID, expiry/status и решение `keep/delete`. Клиенты с одной записью помечаются `unchanged`.

Apply сначала повторно проверяет неизменность инвентаря. Канонический используемый ключ сохраняется без PATCH/reissue. Лишние записи удаляются только через существующий subscription lifecycle, чтобы удаленная и локальная стороны не разошлись. При удаленной ошибке запись остается для безопасного повтора, а миграция не переключает пользователя на новый ключ.

Точечные правила:

- `vssarovv`: точное совпадение username, ровно ожидаемый набор подписок, сохранение активной и удаление старой; иначе stop.
- `sallyqx`: точное совпадение username, удаление только записи, связанной с точным `Tariff.name = "Обычный ВПН"`, сохранение «Стандарт»; иначе stop.

Массовое удаление по одному username или названию тарифа запрещено.

## Ошибки и безопасность

- Все денежные и subscription-операции идемпотентны по payment/operation id.
- Авторизация проверяет фактического владельца или получателя подарка.
- Параллельные webhook, balance и admin операции сериализуются на клиенте.
- Устаревший conversion quote отклоняется без частичного применения.
- Ошибка после удаленного изменения отражается в sync state и audit log; новый UUID как fallback не создается.
- Sensitive URL не пишется в обычные application logs.

## Проверки

Разработка идет TDD. Обязательные сценарии:

- один UUID и одна ссылка после trial -> paid и paid -> другой тариф;
- первая покупка без trial получает минимальный trial-бонус ровно один раз;
- активный/использованный trial не получает двойной бонус;
- upgrade `ceil`, minimum-one-day guard, downgrade `floor` с 5%, same-tariff renewal;
- preview совпадает с применением, устаревший quote отклоняется;
- webhook, баланс, подарок, админка и auto-renew используют каноническую запись;
- параллельные операции не создают второй UUID;
- reissue сохраняет тариф/expiry/лимиты, меняет только short UUID, соблюдает 6 часов и не расходует лимит при ошибке;
- multi-режим можно снова включить без изменения схемы;
- dry-run миграции не пишет данные;
- apply не меняет клиентов с одной подпиской;
- точечные сценарии `vssarovv` и `sallyqx` сохраняют требуемые активные ключи и останавливаются при неоднозначности.

Финальная проверка: полный backend test suite, bot test suite, frontend production build и отдельное ревью безопасности/конфликтов всех точек активации.

## Вне scope

- Обновление зависимостей и устранение существующих `npm audit` предупреждений.
- Переименование legacy `stealthnet` технических идентификаторов.
- Удаление возможности multi-подписок из схемы или интерфейсов навсегда.
