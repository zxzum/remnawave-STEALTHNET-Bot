# Интеграция нового лендинга «Лазейка ВПН»

## Цель

Заменить текущую главную страницу на дизайн из `/Users/sallyqx/Documents/projects/lazeika_landing`, сохранив единое приложение, существующий backend и рабочие пользовательские сценарии на `https://bot.lazeika.xyz`.

## Архитектура

Новый лендинг встраивается в существующий React/Vite frontend и становится реализацией корневого маршрута `/`. Отдельный frontend-сервис, новый backend и новая база данных не создаются. Кабинет, админка, юридические страницы и API остаются в текущем приложении.

Структура и стили целевого макета переносятся с минимальной адаптацией. Данные лендинга преобразуются в его визуальную модель на клиенте через существующие публичные API.

## Данные и пользовательские сценарии

- Бренд, логотип и публичные настройки загружаются из существующего public config.
- Тарифы и цены загружаются из существующего `/api/public/tariffs`; статические карточки макета используются только как безопасный fallback при недоступности API.
- FAQ и редактируемые тексты загружаются из существующего landing API; при отсутствии значения используется текст макета.
- Кнопки входа и регистрации ведут на `/cabinet/login` и `/cabinet/register`.
- Кнопки выбора тарифов ведут в существующий flow регистрации и выбора тарифа без создания нового checkout.
- Telegram-бот, поддержка, оферта и политика используют существующие ссылки и маршруты.
- UTM-параметры сохраняются существующим механизмом frontend.

## Ошибки и доступность

Недоступность landing API не блокирует главную страницу: она отображает встроенный контент макета. Недоступность списка тарифов показывает fallback-карточки, но не создаёт ложного успешного платежа. Интерактивные элементы сохраняют клавиатурное управление, доступные названия и корректные состояния.

## Проверка

- Контрактная проверка преобразования backend-данных в карточки лендинга.
- Production-сборка существующего frontend.
- Визуальная проверка desktop и mobile, меню, тарифов, FAQ и CTA.
- Smoke-проверка production URL, API, входа, регистрации и юридических страниц после деплоя.

## Деплой

Деплой выполняется точечно для frontend на текущем сервере. Перед заменой frontend bundle создаётся резервная копия. Существующие незакоммиченные изменения backend и других файлов на сервере не перезаписываются и не очищаются.
