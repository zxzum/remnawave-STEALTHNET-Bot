# Составные подписки STEALTHNET — дизайн

**Статус:** согласовано для плана реализации
**Дата:** 2026-07-15

## Цель

STEALTHNET остаётся единственным источником истины и внутренней прослойкой между пользователем и Remnawave. Одна логическая подписка STEALTHNET объединяет один или несколько пользователей Remnawave в одну стабильную публичную ссылку `https://bot.lazeika.xyz/api/sub/{token}`.

Пользователь не видит UUID, upstream URL или смену внутренней структуры. Администратор видит и управляет каждым компонентом.

## Термины и инварианты

- **Логическая подписка** — одна запись `Subscription`, различаемая для пользователя индексом: `0`, `1`, …
- **Компонент** — один Remnawave-пользователь в логической подписке: например `sallyqx_0` и `sallyqx_c_whitelist_0` принадлежат подписке `0`.
- **Обязательный компонент** — основной компонент, без которого подписка недоступна.
- **Необязательный компонент** — дополнительный набор доступа; его временная ошибка не ломает основной доступ.
- У подписки один неизменный `publicSubscriptionToken`, пока администратор явно не перевыпустит публичную ссылку.
- У каждой подписки ровно один обязательный компонент и произвольное число компонентов.
- Срок, пользовательский статус и лимит устройств — общие для всех компонентов. Squad, трафик и его сброс — свойства компонента.
- STEALTHNET хранит желаемое состояние; Remnawave исполняет и возвращает фактическое техническое состояние.

## Модель данных

`Subscription` дополняется полями `publicSubscriptionToken`, статусом синхронизации, причиной/счётчиком ошибки, временем повторной синхронизации и связью `components`.

`RemnawaveComponent` содержит: `subscriptionId`, стабильный `key`, отображаемое имя, признак обязательности, порядок merge, `remnawaveUuid`, snapshot squads, лимит и стратегию сброса трафика, настройки показа квоты и статус последней синхронизации.

`TariffRemnawaveComponent` хранит шаблон компонента тарифа. При выдаче или изменении подписки шаблон материализуется в snapshot компонента; правка тарифа не меняет действующие подписки сама по себе.

Старые `Subscription.remnawaveUuid` и `Client.remnawaveUuid` временно зеркалят UUID обязательного компонента. Existing Subscription без компонентов читается как legacy main-компонент до идемпотентного backfill. Это сохраняет действующие данные и текущие ссылки пользователей.

## Публичная подписка

Сохраняется URL и формат `GET /api/sub/:token` на `bot.lazeika.xyz`.

Обработчик находит логическую подписку, передаёт только разрешённые device-заголовки в каждый upstream Remnawave запрос, и объединяет совместимые успешные ответы. Обязательный компонент обязан ответить успешно. Необязательные компоненты загружаются независимо; ошибка одного фиксируется для reconciliation, но не отключает основной доступ.

Поддерживаются безопасные объединения Base64 URI и известных JSON-контейнеров. Неизвестный или YAML-формат не склеивается вручную: возвращается ответ обязательного компонента. В ответ не попадают UUID и upstream URLs.

## Операции

### Выдать и продлить

Создание, покупка, trial, подарок, ручная выдача и авто-продление изменяют логическую подписку в STEALTHNET, материализуют или обновляют компоненты, затем применяют состояние в Remnawave. Успех обязательного компонента достаточен для фиксации оплаты; ошибки остальных компонентов переводят подписку в `PENDING/ERROR` и ставят повторную синхронизацию.

### Отозвать

«Отозвать подписку» означает аннулировать одну логическую подписку, а не перевыпустить URL.

1. STEALTHNET ставит подписку в состояние удаления и запрещает выдачу её публичного URL.
2. Для каждого компонента вызывается Remnawave revoke.
3. После успеха всех вызовов удаляются компоненты, `Subscription` и её публичный токен.
4. Другие подписки пользователя остаются без изменений.
5. Пользователь получает уведомление Telegram-ботом; Telegram-канал уведомлений получает результат и UUID/ошибки для администратора.

Если хотя бы один компонент не отозван, данные не удаляются: сохраняется состояние `PENDING_DELETE`, ошибка и задача reconciliation. Пользовательское уведомление об успешном отзыве не отправляется до фактического завершения; канал получает ошибку сразу.

### Другие действия

- **Отключить/включить:** меняет доступ всех компонентов, но не удаляет подписку.
- **Перевыпустить публичную ссылку:** меняет только `publicSubscriptionToken`, инвалидируя старый URL; не является отзывом.
- **Синхронизировать:** применяет сохранённый STEALTHNET snapshot ко всем компонентам и показывает итог по каждому.
- **Удалить компонент:** удаляет только выбранный дополнительный компонент; обязательный нельзя удалить, пока не назначен другой обязательный.
- **Изменить компонент:** администратор может добавить, удалить или поменять компонент действующей подписки. Новый компонент по умолчанию наследует срок и лимит устройств подписки, но получает свои Squad/traffic policy.

## UI и API-контракт

Все поверхности получают единый read model логической подписки: идентификатор/индекс, тариф, срок, статус, единый `subscriptionUrl`, агрегированные устройства и трафик, sync status, список компонентов и доступные действия.

### Админка

Карточка подписки показывает публичную ссылку и раскрываемую таблицу компонентов: имя, key, UUID, squads, квота, срок, статус Remnawave и ошибку синхронизации. Действия разделены на уровень подписки и компонента, с явными подтверждениями разрушительных операций. Админ может вручную добавлять и удалять дополнительные компоненты, выбирать обязательный компонент, редактировать его параметры и запускать повторную синхронизацию.

Выдача и продление в админке используют тот же поток, что платежи. Никакая форма не отправляет или не показывает техническую upstream-ссылку вместо `subscriptionUrl`.

### Кабинет и Telegram-бот

Показывают только логические подписки, их индекс, срок, тариф, агрегированное состояние и единый публичный URL. Старые кнопки, передающие `root|secondary`, переводятся на `subscriptionId`. Пользовательские операции применяются к логической подписке; UUID и компоненты скрыты.

### Оповещения

Успешный отзыв отправляет пользователю Telegram-сообщение. Все результаты выдачи, отзыва, ручной синхронизации и частичных ошибок отправляются в настроенный Telegram-канал уведомлений. В уведомлении канала указываются subscription ID, индекс, компонент и ошибка; публичный токен и полный HWID не логируются.

## Синхронизация и устойчивость

Существующий `sync.service.ts` получает reconciliation компонентов, без отдельного сервиса-процесса. Он обрабатывает pending/error подписки, сравнивает Remnawave с component snapshot, повторяет безопасные операции и не создаёт новых `Client` при импорте Remnawave UUID.

Все внешние команды должны быть идемпотентны. Частичный сбой не скрывается: он остаётся видимым в админке и уведомлении канала до успешного повторного выполнения.

## Миграция и совместимость

1. Добавить таблицы и поля без удаления legacy колонок.
2. Backfill: существующий `Subscription.remnawaveUuid` превращается в обязательный component; текущий публичный токен сохраняется.
3. Проверить уникальности, связи owner/subscription/component и соответствие legacy UUID.
4. Перевести read paths на единый контракт, затем write paths.
5. Только после регрессии удалить устаревшие UI-контракты и legacy write paths; legacy read fallback остаётся на переходный период.

## Проверка

Покрываются unit-тестами merge и инварианты компонентов, integration-тестами выдача/продление/отзыв/частичный сбой/reconciliation, а также контрактными тестами API для админки, кабинета и бота.

Перед развёртыванием выполняются миграция на копии БД, backfill-аудит, полный backend/frontend/bot test+build, проверка старой публичной ссылки и ручной smoke-test всех административных действий. SSH-развёртывание выполняется только после успешной проверки и отдельного подтверждения пользователя.
