# Синхронизация Telegram username

## Цель

Обновлять `Client.telegramUsername`, когда Telegram передаёт пользователю новый непустой username, без фонового опроса и без записи в базу при каждом действии.

Если пользователь удалил username, сохранённое значение не очищается.

## Потоки

### Telegram Mini App

Endpoint `/api/client/auth/telegram-miniapp` получает актуального пользователя из проверенного Telegram `initData`. Для существующего клиента он сравнивает непустой `username` с `telegramUsername` и обновляет запись только при различии. Ответ авторизации содержит актуальное значение.

### Telegram-бот

Общий middleware бота извлекает `ctx.from.id` и непустой `ctx.from.username` из любого входящего действия пользователя: сообщения, команды или callback-кнопки.

Бот хранит последнее успешно синхронизированное значение в памяти по Telegram ID. Запрос к backend выполняется только при первом действии пользователя после запуска процесса или при изменении username. После неудачного запроса значение не считается синхронизированным, чтобы следующее действие повторило попытку.

Backend принимает запрос только с действительным токеном бота и выполняет условное обновление клиента по Telegram ID: запись изменяется лишь когда переданный непустой username отличается от сохранённого. Отсутствующий клиент не создаётся этим запросом.

## Нагрузка и ошибки

- Нет cron-задач и запросов к Telegram API.
- Пустой или отсутствующий username не вызывает запрос и не изменяет базу.
- Неизменившийся username после заполнения локального кэша не вызывает запрос.
- После перезапуска процесса приходится не более одного запроса на каждого активного пользователя при его первом действии.
- Ошибка синхронизации не мешает обработке действия пользователя; обновление является best-effort.

## Проверка

Минимальные тесты подтверждают:

1. Mini App обновляет отличающийся непустой username существующего клиента.
2. Пустой username не очищает сохранённое значение.
3. Backend бота изменяет только отличающийся username и отклоняет запрос без действительного токена.
4. Middleware не повторяет синхронизацию неизменившегося username и повторяет её после ошибки.
