# Привязка Telegram-аккаунта и журнал ошибок

## Цель

Связывать веб-аккаунт Лазейка ВПН с аккаунтом, созданным через `/start`, в обоих направлениях без ложного сообщения об успехе и без потери подписок. Любое исключение Telegram API должно попадать в настроенную группу уведомлений вместе с безопасным контекстом пользователя.

## Правила объединения

- Сначала создаётся предпросмотр, затем пользователь подтверждает объединение в Mini App или боте.
- Инициирующий аккаунт остаётся основным; Telegram ID переносится на него только после успешного завершения операции.
- Активные trial-подписки не суммируются: сохраняется вариант с более поздним `expireAt`.
- Две подписки одного тарифа суммируются по оставшемуся времени; перед подтверждением показывается итоговая дата.
- Разные тарифы по умолчанию сохраняются обеими подписками. В предпросмотре доступны варианты оставить обе, конвертировать в тариф первой или в тариф второй; количество дней считается по цене за день и округляется вниз.
- Нельзя молча удалить полноценную учётную запись с конфликтующими email/паролем/OAuth-идентификаторами. В таком случае операция останавливается с понятным сообщением.
- После записи результат перечитывается и успех возвращается только если Telegram ID действительно записан у основного аккаунта.

## Ошибки

Бот перехватывает ошибки всех вызовов Telegram API через общий middleware и отправляет их backend-эндпоинту. Backend проверяет секрет бота, находит клиента по Telegram ID и отправляет HTML-экранированное сообщение в `notificationTelegramGroupId` с резервом на admin IDs. В лог не попадают пароль, токен бота или полный непроверенный payload.

Сообщение содержит серверное и клиентское время, метод Telegram, текст/stack ошибки, ID клиента, email, Telegram ID/username и идентификаторы update/chat/message.
