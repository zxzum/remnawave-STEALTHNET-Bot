# Надёжная привязка Telegram и одноразовый welcome

## Цель

Сделать привязку Telegram в кабинете Лазейка ВПН рабочей на iPhone Safari и Яндекс.Браузере, убрать повторные уведомления, добавить безопасную отвязку и привести `/start`, welcome и главное меню к ожидаемому сценарию.

## Решение

### Привязка из кабинета

- Сохранить существующий одноразовый код и срок его действия.
- Открывать Telegram в рамках исходного пользовательского действия: сначала синхронно создать вкладку-заглушку, затем после ответа API направить её на deep link. Если браузер заблокировал вкладку, использовать переход текущей страницы.
- Хранить одну активную сессию привязки в `AppProvider`. Повторной кнопкой не создавать второй код, второй polling или второй success toast.
- Завершать проверку также по `pageshow`, чтобы восстановление страницы из bfcache на iOS корректно обновляло статус.
- После фактической записи `telegramId` показывать ровно одно уведомление об успехе.

### Сообщение после привязки

- При успешной привязке из Mini App backend best-effort отправляет пользователю сообщение через существующий Telegram notification service.
- Сообщение содержит Web App-кнопку «Открыть главный экран» с URL кабинета.
- Ошибка отправки уведомления не откатывает уже успешную привязку.
- При привязке через deep link бот отвечает успехом и кнопкой callback `menu:main`, чтобы пользователь мог открыть главное меню прямо из сообщения.

### Welcome и `/start`

- Использовать существующий `client.onboardingCompleted` как признак того, что welcome уже был показан; новую колонку не добавлять.
- Отмечать поле сразу при первом показе welcome, а не только после нажатия «Главное меню» или завершения настройки.
- Если у клиента уже установлен `trialUsed`, welcome не показывать, даже если старое значение `onboardingCompleted` ещё равно `false`; в этом случае также зафиксировать onboarding как завершённый.
- После первого показа welcome последующие `/start` ведут в главное меню.
- Добавить существующую кнопку trial в раскладку главного меню. Существующая проверка доступности trial остаётся источником истины.

### Отвязка Telegram

- Добавить защищённый endpoint клиента и кнопку в разделе аккаунта.
- Перед отвязкой проверять, что у аккаунта есть альтернативный способ входа: email/пароль, Google или Apple. Для bot-only аккаунта возвращать понятную ошибку и не очищать Telegram ID.
- При успешной отвязке очищать `telegramId`, `telegramUsername` и флаг недоступности Telegram, а незавершённую заявку на привязку удалять.
- Backend остаётся источником истины для проверки доступа; UI только запускает действие и обновляет профиль.

## Границы и риски

- Push/WebSocket для отслеживания привязки не нужен: текущая проверка при возврате в браузер покрывает этот сценарий.
- Раздельный флаг `welcomeSeen` не вводится. Это сохраняет минимальный diff и соответствует текущему смыслу `onboardingCompleted` в настройках `botWelcomeShowOnce`.
- Уведомление из backend является best-effort: сетевой сбой Telegram не должен превращать успешную привязку в ошибку.

## Критерии готовности

- В Safari и Яндекс.Браузере на iPhone кнопка привязки открывает Telegram либо выполняет понятный fallback-переход.
- Один пользовательский запуск привязки даёт не более одного запроса/проверки и одного success toast.
- После привязки из Mini App бот присылает кнопку открытия кабинета.
- После первого welcome повторный `/start` открывает главное меню; при использованном trial welcome пропускается.
- Если trial не активирован, он доступен из главного меню.
- Telegram можно отвязать от аккаунта с альтернативным входом; bot-only аккаунт защищён от потери доступа.
- Backend и frontend проверки проходят.
