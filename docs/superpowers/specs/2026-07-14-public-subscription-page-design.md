# Публичная страница составной подписки

## Цель

Один URL `/api/sub/:publicSubscriptionToken` должен работать как страница подключения в браузере и как subscription endpoint во всех VPN-клиентах. Пользователь видит одну подписку STEALTHNET и не видит внутренних Remnawave-пользователей.

## Выбранная архитектура

Существующий `publicSubscriptionRouter` выполняет content negotiation до загрузки конфигураций:

- обычный браузер с `Accept: text/html` получает самодостаточный HTML без внешних JS/CSS;
- известные VPN-клиенты и неизвестные небраузерные клиенты продолжают получать существующий объединённый Base64/JSON либо безопасный Main fallback;
- отдельный публичный endpoint и отдельный frontend bundle не создаются.

Это устраняет текущую причину пустой страницы: HTML Remnawave содержит абсолютные ссылки `/assets/...`, которые на домене STEALTHNET возвращают 404.

## Источник настроек

Страница читает `system_settings.subscription_page_config` — то же значение, которое редактирует вкладка «Страница подписки» в админке. Кнопка «Перезагрузить с сервера» и загрузка JSON уже наполняют редактор данными из примонтированного `subpage-00000000-0000-0000-0000-000000000000.json`; после сохранения этот JSON становится публичной конфигурацией.

Если сохранённый JSON отсутствует или повреждён, страница остаётся рабочей: показывает данные подписки, копирование URL и быстрый Happ, но не выдумывает список приложений.

## Данные страницы

- название тарифа или trial;
- статус и дата окончания логической подписки;
- Main как «Безлимит»;
- каждый компонент с `showQuotaToClient=true` отдельной карточкой: лимит, использовано, осталось, дата сброса;
- публичный URL с кнопкой копирования;
- быстрые действия Happ и INCY;
- все платформы, приложения, инструкции, внешние и subscription-кнопки из сохранённого JSON.

Плейсхолдеры `{{SUBSCRIPTION_LINK}}`, `{{HAPP_CRYPT3_LINK}}`, `{{HAPP_CRYPT4_LINK}}` заменяются публичным URL. `{{USERNAME}}` не раскрывает внутреннее имя и заменяется пустой строкой.

## Безопасность и ошибки

- весь текст из JSON и Remnawave экранируется перед вставкой в HTML;
- `javascript:`, `data:` и `vbscript:` ссылки блокируются;
- токен не записывается в логи страницы и не передаётся третьим сторонам;
- ошибка дополнительного компонента не ломает страницу: его квота отображается как временно недоступная;
- отсутствие обязательного компонента использует существующий ответ об ошибке подписки.

## Внешний вид

Всегда используется обычная тема STEALTHNET: светлый фон, сине-фиолетовый акцент, стандартные карточки и адаптивная одна колонка на мобильных. Stealth-тема и переключатель темы на этой публичной странице не применяются.

## Проверка

- unit: browser negotiation, HTML escaping, placeholder replacement, blocked URL schemes, список приложений и квоты;
- regression: Happ/V2RayTun/Koala/default продолжают получать прежние форматы;
- browser: desktop и mobile, отсутствие console errors и 404 assets;
- production smoke: одна и та же ссылка возвращает HTML браузеру и subscription body VPN-клиенту.

## Отклонённые варианты

1. Проксировать `/assets` Remnawave — конфликтует с assets STEALTHNET, сохраняет чужой дизайн и не связывает страницу с админкой.
2. Создать новый SPA route и metadata API — добавляет второй endpoint, nginx rewrite и дублирует уже существующую выдачу.
