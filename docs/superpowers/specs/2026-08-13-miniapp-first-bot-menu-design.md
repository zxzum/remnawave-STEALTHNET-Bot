# Mini-app-first главное меню бота Лазейки ВПН

## Цель

Сохранить полезную onboarding-воронку первого запуска в Telegram-боте, но после её завершения убрать дублирующую навигацию и бизнес-логику из обычного главного меню. Главное меню становится плоской точкой входа в mini-app, за исключением продления подписки, где пользователь по-прежнему выбирает способ оплаты и получает ссылку на оплату прямо в боте.

## Безопасность изменений

- Текущая версия бота сохранена в ветке `codex/backup-bot-menu-before-redesign` на коммите `fa0c73f`.
- Реализация выполняется только в ветке `codex/miniapp-first-bot-menu`.
- Незакоммиченные пользовательские изменения вне `bot` не входят в backup и не изменяются этой работой.
- Исторические технические имена `stealthnet` сохраняются; пользовательское название — только «Лазейка ВПН».

## Сохранённая onboarding-воронка

Для нового пользователя без завершённого onboarding остаётся текущая последовательность:

1. Приветствие.
2. Кнопка «Активировать пробный период».
3. Выбор единственного доступного пробного тарифа.
4. Активация пробного периода.
5. Инструкция по подключению.
6. Проверка факта подключения и обновление статуса.
7. Переход в обычное главное меню.

Внутренние шаги этой воронки не считаются подменю главного меню и не удаляются. Повторный вход пользователя с завершённым onboarding сразу открывает новое главное меню.

Покупку платного тарифа внутри onboarding не расширяем: основной путь оплаты после знакомства с сервисом находится в mini-app. Уже существующие необходимые действия onboarding не ломаются и не переписываются без необходимости.

## Главное сообщение

Существующий баннер главного меню сохраняется. Под ним бот формирует компактный текст из актуальных серверных данных:

```text
👋 Добро пожаловать в Лазейка ВПН!

🛡 Ваша подписка: 🟢 Активна
📅 Дата окончания: 13 сентября 2026
☁️ Белый интернет: 12 ГБ из 50 ГБ
📊 Общий трафик: 67 ГБ · безлимит

📦 Ваш тариф: Стандартный · 299 ₽/мес.
🌐 Включено: 50 ГБ белого интернета

Выберите действие 👇
```

Правила отображения:

- Статус нормализуется до понятных пользователю значений: «Активна», «Истекла», «Ограничена» или «Отключена».
- Для активной подписки показывается дата окончания; при отсутствии корректной даты — `—`.
- Строки белого интернета показываются только для тарифа, где доступна соответствующая квота.
- Общий трафик показывает использованный объём и лимит; при отсутствии лимита используется «безлимит».
- Стоимость и название берутся из текущего тарифа. Недоступные необязательные значения не заменяются выдуманными данными: соответствующая часть строки скрывается.
- Для пользователя без подписки показывается «Ваша подписка: 🔴 Не активна», без даты и трафика, а тариф — «не выбран».
- Старые подробные списки подписок, баланс, ссылка подписки, число устройств, прогресс-бары и произвольный инфо-блок из главного сообщения удаляются.
- Существующая поддержка Telegram custom emoji сохраняется там, где она уже применяется.

## Кнопки главного меню

Фиксированная раскладка:

```text
[          👤 ВОЙТИ В КАБИНЕТ          ]  зелёная
[ 💳 Тарифы             ][ 🔑 Мои ключи ]  синие
[ 🤝 Рефералка          ][ 🛠 Поддержка  ]  синие
[ 🔄 Продлить           ][ ℹ️ Инфо       ]  синие
[             ⚙️ Админ-панель           ]  синяя, только администратору
```

Поведение:

- «ВОЙТИ В КАБИНЕТ» — Web App URL `/cabinet`.
- «Тарифы» — Web App URL `/cabinet/tariffs`.
- «Мои ключи» — Web App URL `/cabinet/subscribe`, существующий экран подключения/ключей.
- «Рефералка» — Web App URL `/cabinet/referral`.
- «Поддержка» — обычная URL-кнопка на настроенного support-бота. При отсутствии ссылки кнопка скрывается.
- «Продлить» — callback-кнопка. Она открывает единственное разрешённое подменю: выбор доступного способа оплаты для текущего тарифа. После выбора бот создаёт платёж существующим backend API и показывает прямую кнопку перехода к провайдеру. Существующая серверная обработка webhook, активация и Telegram-уведомление остаются источником истины.
- «Инфо» — обычная callback-кнопка-заглушка с коротким сообщением «Раздел скоро появится» и кнопкой возврата в главное меню.
- «Админ-панель» — существующая callback-кнопка админ-панели; отображается только пользователям из текущего списка администраторов.

Кроме выбора оплаты для «Продлить», пользовательские подменю из обычного главного меню больше не доступны.

## Продление и ошибки

- Если у пользователя нет активного текущего тарифа, «Продлить» объясняет, что продлевать нечего, и предлагает открыть «Тарифы» в mini-app.
- Если тариф больше недоступен или продление запрещено сервером, сообщение использует ошибку backend и не создаёт локальных обходов.
- Если доступен один способ оплаты, экран выбора всё равно показывается единообразно; пользователь явно подтверждает способ.
- Если способов оплаты нет, бот сообщает, что онлайн-оплата временно недоступна.
- Повторное нажатие не должно само по себе активировать доступ: активация происходит только после подтверждения платежа backend-ом.
- Callback/return URL провайдера остаётся навигационной подсказкой, а не доказательством оплаты.

## Минимальная реализация

Используется существующая инфраструктура:

- текущий `buildMainMenuText` упрощается вместо создания второго formatter;
- текущий `mainMenu` получает фиксированную раскладку;
- существующий `web_app` механизм расширяется маршрутами тарифов, ключей и рефералки;
- существующие handlers выбора провайдера и создания платежа переиспользуются для «Продлить»;
- onboarding handlers, серверные webhook-и, сверка Platega и уведомления не переписываются.

Новая база данных, очередь событий, отдельный платёжный сервис и дублирующие React-экраны не требуются.

## Проверка

Один компактный набор проверок должен подтвердить:

1. Новый пользователь всё ещё проходит trial → подключение → главное меню.
2. Возвращающийся пользователь сразу получает плоское главное меню.
3. Главное сообщение корректно отображает активную, истёкшую и отсутствующую подписку, лимитированный и безлимитный трафик.
4. Web App кнопки ведут в правильные маршруты, support использует внешний URL.
5. «Админ-панель» видна только администратору.
6. «Продлить» показывает способы оплаты и переиспользует текущий платёжный поток.
7. Старые пользовательские подменю не присутствуют в главной клавиатуре.

## Вне текущего изменения

- Удаление процесса бота целиком.
- Перенос onboarding в mini-app.
- Переработка админ-панели бота.
- Изменение webhook контрактов платёжных провайдеров.
- Полное удаление старых handlers, пока они могут использоваться onboarding или админскими сценариями; сначала они становятся недоступны из нового пользовательского меню.
- Унификация экрана ожидания оплаты во всех разделах mini-app — отдельный следующий этап после стабилизации нового меню.
