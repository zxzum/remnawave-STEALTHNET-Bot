# Лазейка ВПН 6.2.0: upstream 6.1.1, Aurora и RollyPay

## Цель

Безопасно перенести полезные изменения из STEALTHNET 6.1.1 в Лазейка ВПН, добавить Aurora как необязательный второй дизайн кабинета и RollyPay как необязательный платёжный провайдер. Текущий интерфейс, платёжные системы и собственная логика подписок остаются основными и не меняют поведение по умолчанию.

## Выбранный подход

Используется выборочный перенос на уровне функций и компонентов. Полный merge или замена файлов upstream не применяются: репозитории не имеют общей Git-истории, а upstream удаляет или заменяет собственные модули Лазейка ВПН.

Рассмотренные альтернативы:

1. Полный merge upstream — отклонён из-за отсутствия общего merge-base и высокого риска потери локальной логики.
2. Изолированный fork upstream с последующим возвратом локальных функций — отклонён как чрезмерно большой и плохо проверяемый объём изменений.
3. Выборочный перенос с feature flags — выбран как минимальный обратимый вариант.

## Изоляция и резервирование

Работа выполняется в ветке `codex/upstream-6.1.1-aurora-rollypay` и отдельном worktree. Исходный `main` не изменяется.

Перед реализацией создаются:

- Git-ветка `codex/backup-main-before-6.2.0-20260823`;
- проверенный Git bundle в `backups/main-before-6.2.0-20260823.bundle`;
- дамп PostgreSQL, если локальный контейнер базы доступен.

Миграции не запускаются на рабочей или production-базе. Проверка миграций выполняется только на временной тестовой базе или чистом Docker volume.

## Перенос исправлений upstream

Переносятся только изменения, которые применимы к текущей архитектуре:

- запрет SVG и других небезопасных форматов пользовательских изображений, а также защитные заголовки для `/api/uploads`;
- единое формирование cookie авторизации Remnawave health-check с поддержкой секретов без двоеточия;
- корректная отправка медиа в Telegram broadcast, сохранение результата задачи и очистка зависших задач;
- проверка YooKassa webhook по фактическому статусу платежа через API, без обязательной зависимости от Basic Auth;
- постоянный Docker volume для файлов резервных копий и ограничение их срока хранения;
- безопасная обработка отсутствующих Remnawave UUID во frontend без замены уже внедрённой совместимости Remnawave v3.

Не переносятся upstream-реализации subscription lifecycle, conversion, auto-renew, link rotation, squad traffic, trial lock и cabinet, потому что в Лазейка ВПН уже существуют собственные версии.

## Aurora

Aurora подключается к существующему механизму выбора дизайна кабинета как отдельное значение `aurora`. Текущее значение и текущий дизайн остаются default. Переключение применяется через существующую настройку, без копирования данных пользователя и без изменения API подписки.

Компоненты Aurora используют существующие API-клиенты, маршруты, данные авторизации и локализацию. Пользовательские тексты и бренд адаптируются под «Лазейка ВПН»; legacy-идентификаторы `stealthnet` сохраняются там, где они нужны для совместимости. Если Aurora выключена, её маршруты и компоненты не влияют на основной UI.

## RollyPay

RollyPay добавляется в существующий реестр платёжных провайдеров. Провайдер выключен по умолчанию и становится доступен только при включённом флаге и заполненных обязательных credentials.

Поток платежа:

1. Backend создаёт локальную запись платежа и запрос RollyPay с идемпотентным идентификатором.
2. Пользователь получает redirect URL.
3. Callback проверяется криптографически и сверяется с API RollyPay перед зачислением.
4. Существующий единый сервис завершения платежа активирует подписку ровно один раз.

Повторный callback возвращает успешный ответ без повторного зачисления. Некорректная подпись, сумма, валюта, получатель или статус отклоняются и логируются без секретов.

## Версия и совместимость

Версия приложения повышается до `6.2.0`. Формат существующих настроек и поведение по умолчанию сохраняются. Новые настройки получают безопасные значения по умолчанию: Aurora не выбрана, RollyPay выключен.

Изменения схемы БД допускаются только для данных RollyPay или новых enum-значений, если существующая модель не может хранить их без миграции. Предпочтение отдаётся уже существующим JSON/settings и моделям платежей.

## Ошибки и откат

- Ошибка Aurora не должна нарушать загрузку текущего кабинета; неизвестное значение дизайна приводит к текущему default.
- Недоступность RollyPay влияет только на создание платежа этим провайдером.
- Ошибки фоновых задач broadcast завершают задачу с явным результатом, чтобы frontend прекращал polling.
- Откат выполняется переключением на backup-ветку или восстановлением bundle; изменения БД, если они понадобятся, сопровождаются обратимой миграцией.

## Проверка

- точечные backend-тесты для валидации upload, health cookie, broadcast result/stale jobs, YooKassa и RollyPay callback;
- frontend-тест или минимальная проверка выбора дизайна и fallback;
- TypeScript typecheck и production build backend/frontend;
- `docker compose config` и проверка именованного backup volume;
- миграции на временной базе, если схема изменится;
- ручной smoke test текущего кабинета, Aurora и выключенного/включённого RollyPay.

## Критерии готовности

- текущий кабинет и текущие платежи работают без изменения настроек;
- Aurora можно включить и выключить независимо;
- RollyPay нельзя использовать без полной конфигурации;
- callback RollyPay не может дважды зачислить один платёж;
- полезные upstream-исправления покрыты проверками;
- сборки и релевантные тесты проходят в изолированной ветке.
