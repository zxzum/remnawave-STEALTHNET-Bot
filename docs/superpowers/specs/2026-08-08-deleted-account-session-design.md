# Обработка удалённого аккаунта в кабинете

## Контекст

После удаления клиента из базы его ранее выданный JWT остаётся в
`localStorage`. Клиентский роутер проверяет только наличие токена, поэтому
кабинет успевает отрисовать сохранённые данные, а первый защищённый запрос
возвращает `401 Unauthorized`. Сейчас это превращается в экран «Не удалось
загрузить кабинет» без выхода из сессии.

## Решение

Различать причины отказа в общем клиентском auth middleware и обрабатывать
потерю сессии в общем frontend API-потоке:

1. `requireClientAuth` возвращает отдельный машинный код, если клиент больше не
   существует (`CLIENT_DELETED`), и отдельный код для заблокированного клиента.
2. API-клиент сохраняет текущий refresh для Telegram Mini App, но после
   окончательного `401` вызывает зарегистрированный обработчик потери сессии.
   Auth-контекст очищает state и `localStorage`; повторный вызов не должен
   зациклить refresh или редирект.
3. Обработчик переводит пользователя на
   `/cabinet/login?reason=account-deleted` для `CLIENT_DELETED` и на нейтральный
   `/cabinet/login?reason=session-expired` для остальных недействительных
   сессий. Страница входа показывает понятное русское сообщение по query-параметру.
4. Публичные auth-эндпоинты и запросы без client JWT не используют этот
   обработчик. Ручной logout и обычный login сохраняют текущее поведение.

## Поток данных

```text
protected /client/* request
  -> requireClientAuth
  -> 401 + code
  -> API refresh attempt (только как сейчас для Mini App)
  -> session-lost callback
  -> clear token/profile
  -> /cabinet/login?reason=...
```

## Ошибки и границы

- Удалённый аккаунт: сообщение «Аккаунт удалён. Войдите снова или
  зарегистрируйтесь заново.»
- Просроченный/отозванный/заблокированный токен: нейтральное сообщение о том,
  что сессия завершена, без утверждения, что аккаунт удалён.
- Никаких изменений в JWT, миграциях, регистрации или повторном создании
  Telegram-аккаунта.

## Проверка

- Source-level regression test проверяет backend-код `CLIENT_DELETED`, общий
  callback API/auth и отображение `reason=account-deleted`.
- Запустить cabinet runtime tests, frontend typecheck/build и `git diff --check`.
- Проверить, что unrelated изменения в рабочем дереве не затронуты.
